# 未解決の問題・既知の制約

最終更新: 2026-11-17（MVP初版）

優先度は **高＝市場検証の前に対応が要る / 中＝検証結果しだい / 低＝当面このままでよい** の目安です。

---

## A. 仕様上そうしている（MVPの対象外）

| # | 内容 | 優先度 |
| --- | --- | --- |
| A-1 | **日付の改ざんを防げない。** 端末の日付を変えれば、別の日の「今日の5問」を先に遊べます。サーバーがないため防ぎようがありません。 | 低 |
| A-2 | **端末間でデータが同期しない。** 機種変更・ブラウザ変更で記録は引き継げません。 | 低 |
| A-3 | **他のプレイヤーのデータを自動収集できない。** localStorageのみのため、テスターにJSONを書き出して送ってもらう必要があります。配布用のURLは用意済み（https://summer3018.github.io/kotoba-hirameki-game/ ）。 | **高**（検証の進め方に直結） |
| A-4 | ブラウザのデータを消すと記録も消えます。バックアップはJSON書き出しのみです。 | 低 |
| A-5 | 広告・課金は未実装です（初期版では実装しない方針）。 | 低 |

---

## B. 品質面で残っているリスク

| # | 内容 | 優先度 |
| --- | --- | --- |
| B-1 | **漢字パズルの「別解」は自動では検出できない。** 例: `花 火 夏 祭 夜 空` からは「火花」「夜空」も作れます。お題の文章で絞る設計にし、69問すべて人の目で見直しましたが、見落としの可能性は残ります。辞書データを持たない限り自動化できません。 | **高** |
| B-2 | **穴埋めの別解も同様。** 正解以外の選択肢を入れても別の言葉になってしまう組み合わせがないか、`docs/questions-review.md` の「他の選択肢を入れた形」欄で確認できるようにしてありますが、判定は人が行います。 | 中 |
| B-3 | **問題が69問しかない。** 練習モードは直近20問を避けるため、繰り返し遊ぶとすぐ一巡します。毎日遊んでもらうには最低でも150〜200問は欲しいところです。 | **高** |
| B-4 | 難易度は `difficulty` の項目を持っていますが、**出題に使っていません**。易しい問題ばかりが続く／難しい問題が偏る可能性があります。 | 中 |
| B-5 | 問題の分類（`category`）も同様に、出題では使っていません。 | 低 |

## C. 動作確認が済んでいない

| # | 内容 | 優先度 |
| --- | --- | --- |
| C-1 | **スマートフォン実機での動作が未確認。** PCのChromeで幅320px・375pxの表示と操作は確認済みですが、実機のタップ感・フォント・効果音は見ていません。 | **高** |
| C-2 | **iOS SafariでのJSONダウンロードが未確認。** iOS Safariはファイル保存の挙動が特殊で、`<a download>` が期待どおり動かない場合があります。動かないときは「画面に表示してコピーしてもらう」などの代替が要ります。 | **高** |
| C-3 | 効果音が実機で意図した音量・音色で鳴るか未確認です。Web Audioの合成音のため、端末によって聞こえ方が変わります。 | 中 |
| C-4 | 日付をまたぐ実時間での動作が未確認です（テストでは日付キーを直接渡して検証しています）。 | 中 |
| C-5 | 画面を開いたままプレイ中に日付が変わった場合、そのセットは開始時の日付のまま進みます。意図した挙動ですが、実機での確認はしていません。 | 低 |

## D. 作りとして改善の余地がある

| # | 内容 | 優先度 |
| --- | --- | --- |
| D-1 | **画面の再描画が毎回まるごと作り直し。** 69問程度の規模では問題になりませんが、アニメーションを増やすとちらつきの原因になります。 | 低 |
| D-2 | **ブラウザの「戻る」ボタンに対応していない。** 履歴を積んでいないため、戻るとページ自体を離れます。 | 中 |
| D-4 | アンケートの自由記述が1000文字まで。保存容量の上限は考慮していますが、長文を書かれた場合の挙動は検証していません。 | 低 |
| D-5 | 連続プレイ日数（ストリーク）を記録していません。「毎日遊びたくなる」仕掛けとしては、次に足す候補の筆頭です。 | 中 |
| D-6 | 読み上げソフト（スクリーンリーダー）対応は最低限（`aria-live` と `aria-label`）です。本格的な対応は未着手です。 | 低 |

---

## E. 次にやるなら（優先順）

1. **実機で1周遊んでみる**（C-1 / C-2）── 崩れや操作しづらさを潰す
2. **問題を150問まで増やす**（B-3）── JSONに足すだけで、実装の変更は不要
3. **テスターへの配布方法とJSON回収の手順を決める**（A-3）
4. **難易度を出題に使う**（B-4）── 1問目はやさしく、後半で上げる
5. **連続プレイ日数の記録**（D-5）── 毎日遊ぶ動機づけ

## 気づいたことの書き足し方

問題そのものの誤りを見つけたら、該当する `src/data/questions.*.json` を直してから次を実行してください。

```powershell
npm run validate
npm run questions:list
npm test
```

それ以外の気づきは、このファイルの表に行を足してください。
