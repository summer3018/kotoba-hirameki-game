# 今日の5問を「共通点型」にする 設計書

- 日付: 2026-11-17
- 対象: `kotoba-hirameki-game`（Vite + TypeScript、素のDOM描画、localStorage、GitHub Pages）
- 状態: 佐俣の承認待ち

---

## 1. なぜ直すのか

佐俣が実機で遊んだ感想は「単調すぎて1日で遊ばなくなりそう」「3問目くらいで同じことの繰り返しに感じた」。

今の「今日の5問」は、3種類のパズルがばらばらに5問出るだけで、1問ごとの流れ（お題→選ぶ→正誤と解説→次へ）が5回同じに続く。5問の間につながりも山場もない。

遊び終わったときに味わってほしいのは **爽快感と達成感**（佐俣）。
そこで、5問を1本の謎にする。

## 2. 何を作るか（体験）

- 1〜4問目は今と同じ3種類のパズル（漢字・連想・穴埋め）。ただし **4問の答えは、その日の1つのテーマで全部つながっている**。
- 5問目は「この4つに共通するのは？」。ひらがなの文字パネルを並べてテーマを答える。
- 解いている途中で「もしかして…」と気づき、最後に「やっぱり！」となるのが狙い。

```
問1 傘   問2 長靴   問3 カエル   問4 あじさい
                ↓
問5  この4つに共通するのは？
     [ つ ][ ゆ ][   ]     ← 下のパネルから選んで並べる
     [ゆ][な][つ][る][め][あ]
     → 正解「つゆ」→ 大きく「梅雨」と表示
```

## 3. 目標・目標にしないこと・失敗とみなすこと

**目標**
- 3問目あたりで「繰り返し」と感じさせない。後半ほど答えがつながって見えてくる。
- 5問目に正解した瞬間を、このゲームでいちばん気持ちいい瞬間にする（音・動き・見せ方を特別にする）。
- 最初に30日分のテーマつきセットを用意する。

**目標にしないこと（今回はやらない）**
- 連続で遊んだ日数・成長など「記録の保存」を使った新しい仕組み（佐俣の指示: まだしない）。今ある結果の保存・JSON書き出しは、そのまま残す。
- 練習モードの作り直し。今の69問を今のまま出し続ける。
- 文字を集めて並べ替える型（C-1）。
- 広告・課金・サーバー。

**失敗とみなすこと（動いていても失敗）**
- 1問目を見ただけでテーマが分かってしまう。
- 1〜4問目のお題・ヒント・解説・選択肢に、テーマの言葉そのものが出てしまう（ネタばれ）。
- 5問目に、テーマとして正しいのに不正解になる答え（別の答え）がある。
- 5問目で手も足も出ず、何もできないまま終わる。

## 4. 考えたやり方（Approaches）

| 案 | 中身 | 良い所 | 難しい所 | 結果 |
| --- | --- | --- | --- | --- |
| A. テンポ型 | 1問ごとの解説の画面をなくし、コンボで勢いをつける | 爽快感。作る量が少ない | 5問のつながりは生まれない | 採らない |
| B. 山場型 | 後半ほど難しくし、5問目を特別な問題に | 達成感 | 流れの単調さは残る | 採らない |
| **C. つながり型** | 4問の答えが5問目の謎の手がかりになる | 一番強い「ひらめき」 | 1日分ずつセットを作る手間 | **佐俣が選んだ** |

Cの中の2つの形:

| 形 | 中身 | 結果 |
| --- | --- | --- |
| C-1 文字あつめ型 | 4つの答えから1文字ずつ取り、並べ替えて言葉にする | 作る手間・別の答えが出る心配が大きいので採らない |
| **C-2 共通点型** | 4つの答えに共通するテーマを当てる | **佐俣が選んだ** |

5問目の答え方:

| 形 | 結果 |
| --- | --- |
| 4択 | まぐれで当たり、達成感が弱いので採らない |
| **文字パネル** | **佐俣が選んだ**。今の漢字パズルと同じ操作。答えの書き方が1つに決まる |
| 自由入力 | 書き方のぶれ（梅雨/つゆ/ばいう）とスマホ入力の手間で採らない |

作る土台は、今のコードに足す形にする（作り直さない）。画面の仕組み・音・保存・テスト・自動公開はそのまま使う。

## 5. 決まっていること

### 5-1. データ

1日分のセットを新しいデータとして持つ（`src/data/theme-sets.json` など）。1セットの中身:

- `id`（例 `T-001`）
- `theme`: 正解のひらがな（例 `つゆ`）。パネルで組み立てる文字列そのもの
- `themeDisplay`: 正解したときに大きく見せる表記（例 `梅雨`）
- `tiles`: 5問目に並べるひらがなパネル。正解の文字＋まぎらわしい文字4つほど
- `finalHints`: 5問目で間違えたときに順に出すヒント（2つ）
- `explanation`: テーマの解説（正解後に表示）
- `questions`: 1〜4問目。今の `KanjiQuestion` / `AssocQuestion` / `FillQuestion` と同じ形。**並び順がそのまま出題順**
- 4問の中に3種類のパズルが最低1つずつ入る

### 5-2. 出題

- 今日の5問 = その日のセット1つ。同じ日なら何度開いても同じセット。
- 4問は **テーマから遠い順**（1問目がいちばん遠く、4問目がいちばん分かりやすい）。順番は作る人がデータの並びで決める。
- 1〜4問目の流れは今と同じ（お題→答える→正誤と解説→次へ）。ヒントの扱い・点数も今と同じ。

### 5-3. 5問目

- 画面の上に、1〜4問目の **正解** を4枚のカードで並べる（間違えた問題も正解を見せる。そうしないと5問目が解けない）。
- 下のひらがなパネルを押して答えを組み立て、「決定」。「1文字もどす」「すべて消す」がある（漢字パズルと同じ操作）。
- 答え直しは3回まで。間違えるたびに `finalHints` を1つずつ出し、カード4枚が一瞬光る。
- 3回とも間違えたら正解を見せて終わる（何もできないまま終わらせない）。
- 正解したら、今までより大きい演出（専用の効果音・動き）で `themeDisplay` と解説を見せる。

### 5-4. 結果画面

- 5問目に正解したか・何回目で正解したかを、いちばん目立つ所に出す。

### 5-5. 問題の確かめ方

自動の検証（`npm run validate`）に、セット用の決まりを足す:
- 1〜4問目のお題・ヒント・解説・選択肢・パネルに、`theme` と `themeDisplay` の文字列が入っていない
- `tiles` で `theme` を組み立てられる
- 4問に3種類のパズルが最低1つずつある
- ID が重ならない、項目が欠けていない

人の目で確かめるための一覧を出す（`npm run questions:list` に足すか、別のコマンド）。テーマ・4問の答え・別の答えになりそうな言葉を確かめる欄を入れる。佐俣がこれを読んで確かめる。

### 5-6. 30日分のセット

最初の30セットは Claude が作り、佐俣が上の一覧で確かめる。

## 6. Claudeが決めたこと（佐俣が直してよい）

- 5問目は3回まで答え直せる。ヒントは2つ。
- 5問目の点数は今の問題より大きくする（例: 1回目で正解200点、2回目150点、3回目100点）。正確な値は作る人が決める。
- 1〜4問目の正誤と解説の画面に、ここまでの答えを小さく並べる（「もしかして」と思わせるため）。
- 練習モードは今の69問のまま変えない。
- 30日を使い切ったら、また1つ目のセットから出す。
- テーマは季節に頼らないものにする（いつ遊んでも成り立つ）。決まった開始日から順に1日1セットずつ回す。季節のテーマは、あとで日付を指定できるようにしてから足す。
- ネタばれの検査は、セットごとに `spoilers`（使ってはいけない言葉の一覧。テーマの別の書き方を含む。例: つゆ・ツユ・梅雨・ばいう）を持たせ、それで調べる。`theme` と `themeDisplay` は自動でこの一覧に入れる。
- 作業は別のブランチで進め、佐俣が30セットを確かめ終えてから main に入れる（main に入れると公開ページに自動で出るため）。確かめた結果だめなセットがあれば、直すか差し替えてから入れる。
- 書き出すJSONの古い項目は今の意味のまま残す。1日分の記録に `format`（今までの形 / 共通点型）と、5問目の正解・答えた回数を足し、古い日と新しい日を区別できるようにする。テスターへの配布はまだ始めていないので、今の記録との食い違いで困る人はいない。

## 7. 作る人に任せること

- データの読み込み方、日付からセットを選ぶ計算（同じ日付なら必ず同じセット、を守ること）
- 今日の途中経過の保存の形の直し方（今の `DailyProgress` は問題IDの並びで判定している。古い保存データが残っていても壊れないこと）
- 5問目の演出の細かい中身、効果音の音色（Web Audioの合成音で）
- 記録のイベント（`analytics.ts`）に、5問目の答え直しの回数などを足すかどうか
- テストの足し方（今の `vitest` に足す）
- README と `docs/open-issues.md` の書き直し
